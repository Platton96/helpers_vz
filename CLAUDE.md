# CLAUDE.md — Helpers VZ (Flutter)

Flutter app for web, iOS and Android. The product's purpose is not defined yet — this repository is
a clean skeleton with the conventions in place. Don't invent features; build what is asked.
The web build is published to Netlify (see `README.md`).

## Structure

Single Flutter package. **No sub-packages, no monorepo** — folders are the only boundary.

```
lib/
  main.dart                     error hooks, configureDependencies(), runApp
  app.dart                      HelpersApp — MaterialApp, theme, localization
  di/di.dart                    get_it registrations, one file
  models/                       freezed domain types + enums (none yet)
  repositories/                 data sources (none yet)
  managers/                     logic shared by a BLoC (none yet)
  services/                     platform/SDK wrappers (CrashReportingService)
  localizations/
    arb/app_ru.arb, app_en.arb  every user-visible string (ru is the template)
    generated/                  `flutter gen-l10n` output — AppStrings, never edit by hand
  ui_kit/                       design tokens + reusable widgets (app_colors, app_text_styles, app_theme)
  ui/
    base_bloc.dart              BaseBloc — every BLoC extends it (guarded handlers)
    home/home_screen.dart       placeholder start screen
test/                           mirrors lib/; helpers/test_app.dart sets up DI and pumps a screen
```

New screen → `lib/ui/<screen>/` with `bloc/` + `widgets/` + `<screen>_screen.dart`.
A widget used by 2+ screens moves to `ui_kit/`.

## Stack

- **State:** `flutter_bloc` — one BLoC per screen, hand-written sealed events + `Equatable` state.
- **Errors never reach the user.** Every BLoC extends `BaseBloc`: each handler runs in a try/catch,
  the error goes to `CrashReportingService.recordError`, then the overridable `handleException`
  hook. `CrashReportingService` only logs today; no crash SDK is wired in.
- **DI:** `get_it`, registered manually in `lib/di/di.dart`. **No `injectable`.**
- **Models:** `freezed` (generated by `build_runner`, `.freezed.dart` committed).
- **Localization:** `flutter_localizations` + ARB (`l10n.yaml`), Russian and English; the device
  locale picks one.
- **Fonts:** `google_fonts` (Unbounded, Golos Text). Tests set
  `GoogleFonts.config.allowRuntimeFetching = false` in `setUpAll` (done by `setUpTestApp`).

## Commands

```bash
flutter pub get          # also regenerates lib/localizations/generated from the ARB files
flutter gen-l10n         # after editing an ARB file
dart run build_runner build   # after editing a freezed model
flutter analyze          # must be clean — zero errors and warnings
flutter test             # must be green
flutter run -d chrome    # or an iOS/Android device
```

**Never run `dart format`** — the code is not in formatter style and it would rewrite every file.

There is no FVM, no Makefile, no DCM, no golden tests, no codegen beyond gen-l10n and freezed —
don't add one without being asked.

## Rules

`.claude/rules/dart-coding.md` loads every session. The rest are scoped by their `paths:` key and
load when you read/edit a matching file — `paths:` triggers on a **read**, not on creating a new
file, so read the matching rule before writing a new file of that kind:

| File | Covers |
|---|---|
| `dart-coding.md` | universal Dart conventions (always loaded) |
| `widget-bloc.md` | widgets, BLoC shape, screen structure |
| `repositories.md` | repositories and models |
| `ui-kit.md` | design tokens, `ui_kit/` widgets |
| `di.md` | `get_it` registration |
| `localized-strings.md` | `AppStrings` |

## Working style

- Smallest correct change; follow the patterns already in the repo.
- **No comments** unless explicitly asked — see `dart-coding.md`.
- Run `flutter analyze` and `flutter test` before reporting a change done, and say what the output
  was. A UI change also needs a widget test at the phone, tablet and desktop sizes from
  `test/helpers/test_app.dart` — widget tests fail on overflow, which catches layout regressions.
- Colors, text styles and sizes go into `ui_kit/`, never inline in a widget.
- Temporary notes, plans and scratch output stay out of the repo — use the session scratchpad.
